# 003. Два метода поиска трассы

**Контекст.** Растровый поиск по сетке даёт предсказуемую инженерную геометрию, но привязан к шагу
сетки и на каждом обходе здания теряет метры. Граф видимости строит кратчайший путь среди
многоугольных препятствий по их углам и не теряет на дискретности, но в плотной застройке вершин
становится много, а геометрия — «косой».

**Решение.** Реализованы оба, метод выбирается пользователем до запуска (`methods=grid|visibility|all`).
При `all` считаются оба и в выдачу попадают оба варианта плюс таблица сравнения.

**Следствия.** Видно, чем методы отличаются на одних данных и одних правилах: длина, стоимость,
показатель S, повороты на километр, время поиска. Единственного представителя метода не отбрасываем
как дубль, иначе сравнивать было бы нечего. Цена — время: при `all` расчёт идёт дольше, поэтому
по умолчанию работает растровая сетка.
