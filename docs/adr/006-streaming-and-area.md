# 006. Потоковое чтение и область расчёта

**Контекст.** ТЗ 3.2 требует обрабатывать файл до 3 ГБ. Первая версия читала GeoJSON целиком:
1,49 млн объектов не помещались в память даже с `-Xmx12g`.

**Решение.** Два приёма. Первый: разбор потоком — объекты обрабатываются по одному, файл целиком
в память не попадает. Второй: для больших файлов сначала идёт быстрый проход, определяющий область
расчёта по точкам присоединения и существующей сети, а на втором проходе в память попадают только
объекты этой области.

**Следствия.** Файл 3,05 ГБ считается за 148 секунд, в память попадают 359 объектов из 1 487 256.
Объекты вне области на трассу повлиять не могут — они физически далеко, и об этом честно написано
в статусе и диагностике. Для очень вытянутых районов область может оказаться большой — тогда
работает обычный потоковый режим.
