# Границы применения решения

**Что решение делает.** Предварительная (предпроектная) трассировка новой тепловой сети в плане
по формализованным правилам техприложения: выбор точек врезки, объединение ОКС, расходы, ДУ,
предельные длины, реконструкция существующей сети по расходам, стоимость и ранжирование вариантов.

**Допущения и ограничения.**
1. Двумерная модель: глубина, продольный профиль, рельеф не учитываются (обязательная часть ТЗ 2.2).
   Режим с учётом глубины — отдельная дополнительная задача.
2. Гидравлика упрощена до пропускной способности и предельной длины по ДУ (ТП §3, §4.1); давление,
   потери напора, насосные режимы не считаются (ТЗ 2.12).
3. Точность геометрии — шаг растровой сетки (2 м по умолчанию): трасса проходит по узлам сетки,
   повороты кратны 45°. Отступы проверяются по центрам клеток, поэтому фактический зазор может
   отличаться от нормативного на величину до половины шага (округление в большую сторону
   допускается — Q&A 16.09). Для более точного результата шаг уменьшается в `rules/routing.yml`
   ценой времени расчёта.
4. Ось полигонального препятствия (дорога, ж/д) строится как длинная сторона минимального
   охватывающего прямоугольника; для сильно изогнутых полигонов угол пересечения оценивается
   приближённо. Для линейных объектов угол считается к ближайшему прямому отрезку.
5. Существующая сеть по геометрии не проверяется (Q&A); при отсутствии `flow_tph` текущий расход
   принимается 0, при отсутствии `upstream_object_id` цепочка восстанавливается по совпадающим концам
   участков (допуск 0,5 м) — расхождения фиксируются в диагностике.
6. Совместное подключение — жадная последовательная стратегия (ближние точки формируют ствол),
   а не глобальная оптимизация дерева Штейнера; варианты дают альтернативы, но оптимальность
   в строгом смысле не гарантируется.
7. Типы ограничений, отсутствующие в правилах, обрабатываются по правилу по умолчанию (запрет с
   отступом 1 м) с предупреждением. Правило для `railway` принято как для трамвайных путей —
   допущение до уточнения постановщиком.
8. Отступ от ОКС берётся по верхней оценке ДУ новой сети (ДУ для суммарного расхода всех точек
   расчёта) — консервативно.
9. Один источник, один экземпляр сервиса; распределённый расчёт не предусмотрен (ТЗ 2.2, Q&A).
10. Входной файл обрабатывается потоково, но объекты одного расчёта держатся в памяти;
    для наборов масштаба города (миллионы полигонов) потребуется дисковое хранилище объектов
    (PostGIS) — архитектурно предусмотрено через слой доступа, в текущей версии не реализовано.

**Универсальность.** Тип ресурса не зашит в код: справочник ДУ/пропускной способности/цен и правила
пересечений — конфигурация, поэтому та же логика применима к водопроводу, канализации, кабельным
линиям при замене справочников (Q&A: критерий дополнительной оценки).
