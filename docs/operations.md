# Эксплуатация

## Запуск

```bash
# оцениваемый контур: сервис и база, без витрины и внешних систем
docker-compose up -d --build

# то же плюс просмотрщик на порту 80
docker-compose -f docker-compose.yml -f deploy/docker-compose.stand.yml up -d

# стенд целиком, с единым входом через Keycloak
KEYCLOAK_PUBLIC_URL=http://<адрес стенда>:8081 docker-compose \
  -f docker-compose.yml -f deploy/docker-compose.stand.yml -f deploy/docker-compose.keycloak.yml up -d
```

Приложение всегда перезапускается **тем же набором `-f`**, что и весь стенд: `docker-compose up -d
--no-deps app` без списка файлов поднимет контейнер по базовому compose, без переменных Keycloak,
и сервис окажется в режиме без проверки токенов.

## Проверка после запуска

| Что | Команда | Ожидается |
|---|---|---|
| Сервис жив | `curl -s -o /dev/null -w "%{http_code}" http://<хост>/api/samples` | `200` |
| Режим доступа | `curl http://<хост>/api/auth/config` | `"mode":"optional"` и непустой `issuer`, если поднимали с Keycloak |
| Правила прочитаны | `curl http://<хост>/api/rules/routing` | параметры трассировки, не пусто |
| Схема результата | `curl -o /dev/null -w "%{http_code}" http://<хост>/api/schema/result` | `200` |
| Расчёт | `curl -F "file=@data/samples/contest_dataset.geojson" http://<хост>/api/process -o r.geojson` | три варианта, лучший 1 901 м |

## Режимы доступа

| Режим | Переменная | Поведение |
|---|---|---|
| Выключен | `HEATNET_SECURITY_MODE=off` | токены не проверяются, все методы открыты; кнопка входа в интерфейсе неактивна и объясняет причину |
| Необязательный | `optional` | работает и без входа, но вошедший пользователь виден в журнале и получает права по ролям |
| Обязательный | `required` | без действительного токена доступ закрыт; так поднимается закрытый контур |

Роли: `catp-admin` (расчёты, правила, журнал), `catp-engineer` (расчёты и просмотр),
`catp-viewer` (только просмотр). Realm, клиент и демонстрационные учётные записи разворачиваются
из `deploy/keycloak/realm-catp.json` — в админке настраивать нечего.

## Данные и состояние

| Что | Где | Переживает перезапуск |
|---|---|---|
| Задания, их статусы и метрики | PostgreSQL, таблица заданий | да |
| Входные файлы заданий | том `heatnet-data`, каталог `input` | да |
| Результаты и объекты области расчёта | том `heatnet-data`, каталоги `result`, `input-area` | да |
| Последний расчёт для просмотрщика | том `heatnet-data`, каталог `last` | да |
| Журнал событий | PostgreSQL | да |

Каталоги задаются переменной `HEATNET_STORAGE` (в образе — `/var/lib/heatnet`). Чтобы очистить
историю, достаточно удалить том: сервис создаст структуру заново.

## Ресурсы

| Нагрузка | Память | Время |
|---|---|---|
| Конкурсный набор (144 объекта) | до 1 ГБ | 20–32 с |
| Набор 10 МБ (4 888 объектов) | до 1,5 ГБ | около 30 с |
| Файл 3,05 ГБ (1 487 256 объектов) | пик 5,9 ГБ при `-Xmx12g` | 148 с |

Параллельные расчёты ограничены числом рабочих потоков очереди (`HEATNET_WORKERS`, по умолчанию 2):
пока идёт большой расчёт, сервис продолжает отвечать остальным.

## Диагностика проблем

| Симптом | Куда смотреть |
|---|---|
| Расчёт завершился ошибкой | `GET /api/jobs/{id}` — поле `error`; `GET /api/jobs/{id}/diagnostics` — что было не так с данными |
| Подозрение на плохую геометрию | диагностика уровня `WARNING`: `CLEARANCE_TIGHT`, `TURN_LIMIT`, `TREE_CROSS`, `DEPTH_CLEARANCE` — в тексте указаны участок и координаты |
| Точка осталась без трассы | диагностика по точке: `ROUTE_RETRY`, `EXIT_ENCLOSED`, `ROUTE_VISIBILITY_FALLBACK` |
| Кто запускал расчёт | `GET /api/events` с фильтрами по типу, уровню и пользователю; у записи есть сквозной идентификатор запроса |
| Контейнер не пересоздаётся | compose 1.29.2 на новых версиях Docker падает с `KeyError: 'ContainerConfig'`, если образ пересобран: удалить контейнер приложения и поднять заново |

## Обновление правил без перезапуска

```bash
# заменить файл правил в контейнере или в смонтированном каталоге, затем
curl -X POST http://<хост>/api/rules/reload
curl http://<хост>/api/rules/reference   # убедиться, что новые значения прочитаны
```
