## 2.11. Обязательный функционал

| Требование | Где в решении |
|---|---|
| Обработка всех перспективных ОКС за один запуск | `POST /api/process`; на конкурсном наборе 17 точек из 17 за один запрос, ручная подготовка маршрутов не нужна |
| Определение мест присоединения к существующей сети | `collectGoals` в `planner/RoutePlanner`: существующая камера при запасе лучей и расстоянии до 10 м, иначе новая камера на участке |
| Построение маршрутов с учётом пространственных ограничений | `planner/ObstacleField` по таблице 2; запреты с отступом по диаметру, специальные проходы с минимальным углом |
| Совместное подключение нескольких ОКС | сборка дерева в `planner/NetworkBuilder`: ближние точки идут общим стволом, дальние присоединяются через камеры |
| Расчёт расходов и подбор условных диаметров | `hydraulics/HydraulicsCalculator`, таблица 1 из `rules/reference.yml` |
| Проверка предельной длины участка одного диаметра | там же, по каждому непрерывному пути; диагностика `LENGTH_LIMIT_UPSIZE` и `LENGTH_LIMIT_EXCEEDED` |
| Устройство тепловых камер и технических узлов | камеры в точках ветвления и присоединения, технические узлы при смене диаметра, способа прокладки или глубины |
| Расчёт стоимости и ранжирование вариантов | `summarize` в `HydraulicsCalculator`; показатель S по §2.9 приложения |
| Распространение расходов по существующей сети, требуемые диаметры, участки под реконструкцию | реконструкция отменена разъяснениями от 21.09.2026, п. 14 — см. [adr/008](adr/008-no-reconstruction.md). Распространение расходов и требуемые диаметры сохранены как информационный расчёт: `hydraulics/ExistingLoadAnalyzer`, поле `existing_network_impact`, блок «Влияние на существующую сеть» в смете и в паспорте варианта |

## 2.12–2.14. Границы, дополнительная задача, универсальность

| Требование | Где в решении |
|---|---|
| Границы задачи: что не требуется | [limits.md](limits.md) — принятые допущения и что сознательно не делается |
| Дополнительная задача: трассировка с учётом глубины | `depth/DepthProfiler`, `depth/DepthRules`, `POST /api/process?depth=true`, [depth.md](depth.md), вкладка «Профиль по глубине» |
| Места пересечений со стороной прохождения и вертикальными расстояниями | `depth_crossings` в сводке варианта; таблица под профилем на экране |
| Универсальность: применимость к другим сетям | профили правил в `rules-profiles/`: тот же код считает водопровод на своём справочнике |

## 3. Технические требования

| Требование | Где в решении |
|---|---|
| Java 11, Spring Boot 2.6.3, Maven | `pom.xml`; см. [adr/001](adr/001-stack.md) |
| PostgreSQL | задания, результаты и журнал событий; `docker-compose.yml` |
| docker-compose 1.29.2, Ubuntu 22.04 | стенд поднят именно этой версией; раздел «Демонстрационный стенд» в README |
| Файл до 3 ГБ (3.2) | потоковый разбор и область расчёта, [adr/006](adr/006-streaming-and-area.md); прогон: 1 487 256 объектов за 148 с |
| Работа офлайн | все зависимости в образе, внешних вызовов во время работы нет |
| Описание API | springdoc-openapi, Swagger UI на `/swagger-ui.html` |

| Критерий | Чем закрыт |
|---|---|
| Подход команды | два метода поиска и обоснование выбора, [adr/](adr/), разбор в [algorithm.md](algorithm.md) |
| Качество трассировки | самопроверка геометрии, сравнение с существующей сетью на вкладке «Сравнение», метрики поворотов и прямых участков в выдаче |

| Техническая проработка | тесты, независимый валидатор, схемы на вход и выход, прослеживаемость результата, файл 3 ГБ |
| Варианты и объяснимость | категории вариантов, пояснения словами, смета, паспорт, диагностика по каждому решению |
| Дополнительная ценность | дополнительная задача целиком, второй метод, влияние на существующую сеть, MCP-сервер, единый вход и журнал, руководство пользователя |
| Питч-сессия | сценарий демонстрации в [demo.md](demo.md) |
