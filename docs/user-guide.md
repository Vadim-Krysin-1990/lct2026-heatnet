и витрина на порту 80, если поднимать со стендовым файлом compose.

## 1. Сколько ждать

| Что происходит | Сколько |
|---|---|
| Первая сборка `docker-compose up -d --build` | 3–6 минут: собирается образ и скачиваются зависимости |
| Конкурсный набор, один метод поиска | около 20 секунд на шести ядрах |
| Конкурсный набор, оба метода | около 32 секунд |
| Набор 10 МБ (4 888 объектов) | около 30 секунд |
| Файл 3 ГБ (1 487 256 объектов) | 148 секунд, через очередь заданий |

Файлы больше 200 МБ сервис принимает в очередь: соединение не держится открытым, состояние
показывается полосой, результат забирается по готовности.

## 2. Что на экране

Слева — панель управления: загрузка данных, выбор метода, запуск расчёта, список вариантов и сводка
по выбранному. Справа — карта. Сверху — вкладки: **Карта**, **Варианты**, **Смета**,
**Профиль по глубине**, **Сравнение**, **Журнал событий**, **Правила расчёта**, **Руководство**,
**ИИ-агент (MCP)**, **О сервисе**.

В правом верхнем углу — кто вошёл и кнопка входа. Стенд открыт без учётной записи: расчёт, карта,
варианты и правила доступны сразу. Вход нужен для журнала событий и правки правил.

При открытии страницы показывается **последний выполненный расчёт**, а не образец: над панелью
появляется плашка «Показан последний расчёт: имя файла, объектов, вариантов, время» и кнопка
«Показать конкурсный образец». Если расчётов ещё не было, открывается конкурсный набор.

## 3. Расчёт своего файла

1. Перетащите GeoJSON в поле **«Исходные данные»** или нажмите на него и выберите файл.
   Под полем появится имя и размер.
2. Выберите **метод поиска** — это делается до запуска:
   * **Растровая сетка** — поиск по клеткам, развёрнутым вдоль застройки. Быстро, геометрия
     предсказуемая.
   * **Граф видимости** — вершины на углах запретных зон, рёбра — прямые между ними. Иногда короче
     в открытом пространстве, считает дольше.
   * **Оба метода** — считает и то и другое, в выдаче будут оба и таблица сравнения.
3. При необходимости включите **«с учётом глубины»** — это отдельный набор вариантов
   с продольным профилем.
4. Нажмите **«Рассчитать на сервере»**. Появится полоса загрузки, затем строка результата,
   кнопка **«Скачать результат (GeoJSON)»** и таблица времени по этапам: подготовка данных,
   поиск каждым методом, инженерный расчёт, итог.

Готовый результат, полученный ранее, открывается без пересчёта: раскройте
**«Показать готовый результат из файла»**, выберите файл и нажмите **«Показать на карте»**.

## 4. Как читать карту

| Что видно | Что это |
|---|---|
| Синие линии разной толщины | новая сеть; толще — больший диаметр, подпись — ДУ |
| Оранжевые участки | специальные проходы: под дорогой, трамвайными путями, газопроводом, кабелем |
| Синие ромбы | новые тепловые камеры |
| Чёрные точки | технические узлы — там меняется диаметр, способ прокладки или глубина |
| Красные линии и квадраты | существующая сеть и её камеры |
| Звезда | источник тепла |
| Зелёные кружки | точки присоединения объектов, в скобках — расход в т/ч |
| Серые полигоны | здания; голубые — вода; охристые — железная дорога |

Наведение на участок показывает диаметр, длину и стоимость, клик закрепляет карточку.
Слои включаются и выключаются по отдельности. Галочка «подложка OpenStreetMap» требует интернета,
на закрытом контуре её можно не включать.

Для больших файлов на карту выносятся объекты вокруг расчётной зоны — в статусе написано, сколько
показано и сколько скрыто: остальные лежат далеко и на трассу не влияют.

## 5. Варианты и почему они в таком порядке

Варианты сгруппированы блоками:

* **Инженерные** — геометрия по практике проектирования: длинные прямые вдоль проездов, прямые углы.
* **Минимальные по расчёту** — лучший показатель S: короче и дешевле.
* **Контрольные** — считаются для сравнения подходов.

У каждого подписаны длина, стоимость и показатель S. Порядок определяется формулой приложения:
S = 0,7 · (стоимость / 25 млн) + 0,3 · (длина / 100); меньше — лучше. Вариант с нарушением
обязательных правил в выдачу не попадает, пока есть чистая альтернатива.

Вкладка **«Варианты»** показывает всё это таблицей: длина, стоимость, S, число врезок, камер и
узлов, время расчёта — удобно объяснять ранжирование.

## 6. Смета и паспорт варианта

Вкладка **«Смета»**:

* стоимость по статьям: участки, камеры, врезки в существующие камеры, штрафы;
* разбор по диаметрам: сколько метров и денег на каждом ДУ;
* **влияние на существующую сеть** — какие её участки принимают добавленный расход и каким из них
  не хватает текущего диаметра;
* кнопка **«Паспорт варианта»** открывает печатную форму: ведомость участков и камер, где у каждой
  строки есть описание словами — «труба ДУ150 в траншее, 47 м, от точки подключения ОКС 7
  до новой тепловой камеры, один поворот 90°, на глубине 3,00 м».

## 7. Профиль по глубине

Вкладка **«Профиль по глубине»** работает для расчётов, выполненных с галочкой «с учётом глубины».
Показывает продольный разрез выбранной цепочки: поверхность, трубу, спуски и полки постоянной
глубины. Ниже — таблица пересечений с коммуникациями: сторона прохождения (сверху или снизу),
расчётное вертикальное расстояние и норма для этого типа.

В конкурсном наборе пересекать нечего — в нём нет газопроводов, кабелей и дорог. Для показа есть
кнопка **«Загрузить пример с коммуникациями»**.

## 8. Сравнение методов и сравнение с эталоном

Вкладка **«Сравнение»** состоит из двух частей:

* **Сравнение методов трассировки** — строка на каждый вариант: метод, длина, стоимость, S,
  поворотов на километр, медиана прямого участка, число косых изломов, время поиска и отдельно
  время инженерного расчёта. Под таблицей — вывод словами, какой метод дал лучший показатель
  и какой искал быстрее.
* **Сравнение с эталоном** — метрики нашей трассы против существующей сети из входного файла:
  она построена проектировщиками и принята в эксплуатацию, поэтому её геометрия и есть образец
  практики.

## 9. Правила расчёта

Вкладка **«Правила расчёта»** показывает то, по чему сервис считал:

* **Справочник расчёта** — таблица 1 приложения: пропускная способность, предельная длина участка
  одного диаметра, цена метра, габариты;
* **Ограничения** — таблица 2 одной читаемой таблицей: вид ограничения, правило (запрет или
  специальный проход), минимальное расстояние, угол пересечения, коэффициент удорожания, поведение
  в режиме глубины и источник числа;
* **Параметры трассировки** — шаг сетки, штрафы за повороты, радиусы поиска кандидатов.

В начале вкладки — нормативная база: что взято из технического приложения, а что из сводов правил,
и единственное место, где решение намеренно расходится с приложением (железная дорога).

Правила лежат в YAML и перечитываются по `POST /api/rules/reload` — без пересборки сервиса.

## 10. Журнал событий и вход

Вкладка **«Журнал событий»**: кто и когда запускал расчёт, какие файлы принимались, чем
закончилось, сколько заняло. Фильтры по типу, уровню и пользователю. У каждой записи есть сквозной
идентификатор запроса, по которому событие сопоставляется с обращением вызывающей системы.

Вход — через Keycloak, кнопка в правом верхнем углу или клик по строке «анонимно».
Демонстрационные учётные записи показаны прямо в окне входа: `admin.catp`, `engineer`, `viewer`,
пароль у всех `catp2026`. Роли различают, кому можно запускать расчёты и править правила,
а кому — только смотреть.

## 11. ИИ-агент через MCP

Вкладка **«ИИ-агент (MCP)»** объясняет, как подключить языковую модель напрямую к расчётам:
скачать `catp_mcp_server.py`, прописать его в настройках MCP-клиента, задать адрес сервиса.
После этого агенту можно поручить: «посчитай эту заявку и сравни оба метода», «покажи участки
существующей сети, которым не хватит диаметра», «собери смету лучшего варианта».
Подробности — [mcp/README.md](../mcp/README.md).

## 12. Пометки, предупреждения и что с ними делать

| Пометка | Что означает | Что делать |
|---|---|---|
| «Требует ручной проработки» у варианта | самопроверка нашла нарушение правил — например, поворот круче 90°, который не удалось срезать по свободному месту | посмотреть координаты в диагностике; вариант выдан потому, что чистых в его категории не нашлось |
| Неподключённые ОКС в сводке | для точки не нашлось допустимого маршрута | причина по каждой точке есть в диагностике; в стоимость входит штраф по приложению |
| «Объектов в файле … , в области расчёта …» | сервис посчитал по объектам вокруг зоны подключения | это нормально: удалённые объекты не могут повлиять на трассу |
| Предупреждения в диагностике (`WARNING`) | данные приняты с оговоркой: восстановленный атрибут, невалидная геометрия, отступ у самой границы | смотреть перечень в `GET /api/jobs/{id}/diagnostics` |

## 13. Если что-то пошло не так

| Симптом | Причина и что делать |
|---|---|
| Кнопка «Войти» неактивна | сервис запущен без единого входа (режим `off`). Проверить: `curl http://<хост>/api/auth/config` — нужен `"mode":"optional"` и непустой `issuer`; поднимать приложение тем же набором файлов compose, что и весь стенд |
| Ответ 422 при расчёте | входные данные не прошли проверку: в теле ответа перечислено, какой объект и чем не подошёл |
| Расчёт долгий и страница «висит» | файл больше 200 МБ — используйте очередь: `POST /api/jobs`, затем `GET /api/jobs/{id}` |
| На карте старые объекты | страница открыта из кэша; перезагрузите с `Ctrl+Shift+R` |
| Не видно профиля по глубине | расчёт выполнен без галочки «с учётом глубины» либо во входных данных нет подземных коммуникаций |
| Нужен результат без интерфейса | `curl -F "file=@input.geojson" http://<хост>/api/process -o result.geojson` |
