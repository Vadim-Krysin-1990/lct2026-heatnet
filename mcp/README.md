# MCP-сервер ЦАТ

Даёт языковой модели прямой доступ к расчётам трассировки: агент сам считает входной файл, читает
варианты, сравнивает методы поиска, поднимает смету, смотрит влияние на существующую сеть и
диагностику. Протокол — MCP (JSON-RPC 2.0 через stdio), транспорт до сервиса — его же REST.

Зависимостей нет: только стандартная библиотека Python 3.8+. Поэтому сервер запускается в закрытом
контуре рядом с сервисом, без доступа в интернет.

## Подключение

```json
{
  "mcpServers": {
    "catp-heatnet": {
      "command": "python3",
      "args": ["/путь/к/mcp/catp_mcp_server.py"],
      "env": { "CATP_URL": "http://localhost:8080" }
    }
  }
}
```

Переменные окружения:

| Переменная | Назначение |
|---|---|
| `CATP_URL` | адрес сервиса, по умолчанию `http://localhost:8080` |
| `CATP_TOKEN` | токен доступа — нужен, если сервис запущен с `heatnet.security.mode=required` |
| `CATP_TIMEOUT` | таймаут запроса в секундах, по умолчанию 1800 (расчёт файла 3 ГБ идёт минутами) |

Проверка без MCP-клиента:

```bash
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | python3 catp_mcp_server.py
CATP_URL=http://13.143.181.167 python3 - <<'EOF'
EOF
```

## Инструменты

| Инструмент | Что делает |
|---|---|
| `service_info` | доступность сервиса, действующие параметры трассировки, список образцов |
| `calculate` | расчёт входного GeoJSON: `methods` (grid / visibility / all), `depth`, `variants`, `save_to`; файл больше 200 МБ уходит в очередь |
| `job_status` | состояние задания очереди, по завершении подхватывает результат |
| `get_variants` | варианты: место, длина, стоимость, S, метод, время по этапам, пометки |
| `compare_methods` | сравнение растровой сетки и графа видимости на одних данных |
| `get_segments` | ведомость участков варианта |
| `get_estimate` | смета варианта по статьям и диаметрам |
| `existing_network_impact` | добавленный расход по цепочке к источнику и требуемые ДУ существующих участков |
| `depth_crossings` | пересечения с коммуникациями: сторона прохождения, вертикальные расстояния |
| `diagnostics` | диагностика задания с фильтром по уровню |
| `get_rules` | действующие правила: `reference`, `restrictions`, `routing` |
| `events` | журнал событий сервиса |

Операций записи в наборе нет, кроме постановки расчёта в очередь: агент читает результаты и правила,
но не меняет ни данные, ни конфигурацию. Все обращения идут через REST и попадают в журнал событий.

Результат последнего `calculate` запоминается в процессе сервера, поэтому остальные инструменты
можно вызывать без пути к файлу; готовый выходной файл передаётся параметром `result_path`.
